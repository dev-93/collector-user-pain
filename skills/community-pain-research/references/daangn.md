# 당근 동네생활

## 공개 웹 구조

- 게시글 URL: `https://www.daangn.com/kr/community/<제목슬러그>-<글ID>/`
  - 글ID는 마지막 `-` 뒤 12자 (예: `tbm5x6a7kmqf`). `원문ID`는 `daangn-community-<글ID>`.
- 동네 검색 페이지: `https://www.daangn.com/kr/community/?in=<동이름>-<지역ID>&search=<검색어>`
  - 검색이 **동네 단위**로 묶여 있다. 전국 키워드 검색이 안 되므로 동네를 하나씩 돌면 비용만 커진다.
- 카테고리: 고민/사연, 생활/편의, 미용, 맛집 등. 사장 하소연은 주로 `고민/사연`에 있다.
- 로그인 없이 본문과 댓글이 보인다.

## 후보 찾는 순서

1. **외부 검색 엔진의 site 검색이 기본**: `site:daangn.com/kr/community "<사장 표현>" "<장면 표현>"`
   - 사장 표현 예: "1인샵 운영중", "가게 운영중", "저희 가게", "장사하는데", "원장입니다", "사장입니다"
   - 장면 표현은 씨앗에 맞춘다: "노쇼", "예약 취소", "알바 안나와", "전화 못 받아", "정산"
2. 동네 검색 페이지는 특정 지역 가설이 있을 때만 쓴다.
3. 게시글 하단의 "근처 동네생활 인기글"에 비슷한 글이 걸리기도 하지만, 보조 탐색으로만 쓴다.

## 게시일 확인

검색 결과의 날짜는 비어 있거나 틀리는 경우가 많다. 원문 HTML에서 직접 확인한다.

```bash
curl -sL -A "Mozilla/5.0" "<URL>" | grep -o 'datePublished":"[^"]*"' | head -1
```

첫 번째 값이 게시글 날짜다. 이후 값은 댓글 날짜일 수 있다.

## 자주 걸리는 노이즈

- 소비자가 업체를 고발·후기 쓰는 글 (예: 청소업체 예약 취소 당함) — 역할이 반대
- "사장님들 노쇼 사기 조심하세요" 같은 안내·홍보성 글 — 실제 피해 사례가 아님
- 직원·매니저·관리자가 쓴 글 — 사장 본인이 아님
- 가게 사과문 — 응대 문제는 보이지만 손실이 명시되지 않음
- 몇 년 전 글이 인기글로 계속 노출됨 — 반드시 게시일 확인
- `동네생활봇` 댓글 요약 — 원문 근거가 아니다

# 당근 카페 (cafe.daangn.com) — 2026-10-13 확인

동네생활과 별개의 온라인 카페 서비스다. 업종 사장들이 모인 카페는 동네 단위 제약이 없어 둘러보기에 더 맞다.

- 확인한 카페: 대한민국 자영업 커뮤니티 `https://cafe.daangn.com/x6idgz` (2026-06 개설, 멤버 약 1.3만)
- 카페 홈은 로그인 없이 최근 글 목록이 보인다. 홈 HTML의 `href="/x6idgz/posts/..."`로 제목 목록을 얻는다.
  외부 검색보다 이 목록에서 제목으로 후보를 고르는 쪽이 빠르다.
- 글 URL: `https://cafe.daangn.com/<카페ID>/posts/<제목슬러그>-<글ID>` (글ID는 마지막 `-` 뒤 8자).
  `원문ID`는 `daangn-cafe-<카페ID>-<글ID>`.
- 공개 글은 HTML의 `application/ld+json`(`DiscussionForumPosting`)에 제목·본문·`datePublished`·작성자 닉네임이 있다.
- **멤버 공개 글이 섞여 있다.** ld+json이 없고 "멤버에게만 공개된 게시글" 문구가 나오면 가입·우회하지 않고 건너뛴다.
- 노이즈: 앱·서비스 추천처럼 보이는 홍보성 글, 업체 대표가 쓴 정보글, 익명 닉네임 `시그니처(익명)`처럼
  짧고 일반적인 질문형 글은 실제 경험인지 판단이 어렵다. 구체적인 사건·날짜·금액이 없으면 경계 사례로 둔다.
- robots.txt: 일반 에이전트는 `/api/`·`/debug/`·`/errors/`·`/-/manage/`만 막혀 있고 글 페이지는 허용.
  공개 API는 없다. 수집은 공개 페이지 읽기로만 한다.
