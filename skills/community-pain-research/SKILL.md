# 커뮤니티 원문 조사 (Problem Radar)

이 스킬은 "원문을 몇 건만 정확하게 확인하는" 사람 주도 조사 흐름이다. 넓게 긁어오는 수집기가 아니다. Problem Radar 저장소의 `AGENTS.md` 원칙(자동 수집 금지, 점수는 힌트, 증거는
사람이 확인한 독립 원문만)이 항상 우선한다. 어느 폴더에서 실행하든 시작 전에
`/Users/taenam/business/collector-user-pain/AGENTS.md`를 읽어 최신 기준을 확인한다.
이 스킬의 원본은 `/Users/taenam/business/collector-user-pain/skills/community-pain-research/`이며,
`~/.config/opencode/skills/`에는 심볼릭 링크만 둔다.

## 고정 범위

- **제외 채널**: 지식iN, Reddit, YouTube, 쿠팡, 스마트스토어, 디시인사이드. 뉴스·일반 블로그·FAQ·상품 설명은 직접 증거가 아니다.
- **우선 채널**: 당근 카페(공개 글). 새 채널은 로그인 없이 본문·게시일이 보이고, 사장 본인 글이 원문 3건 테스트에서
  확인되고, robots.txt가 막지 않을 때만 `references/`에 메모를 추가해 쓴다.
- **하지 않는 일**: 에이전트가 직접 돌리는 자동/백그라운드 수집, 검증 실험실 이관, `validate` 실행,
  로그인·가입·멤버 공개 글 접근·글쓰기·댓글·좋아요.
- **정기 요약 예외**: 당근 카페 하루 1회 요약은 사용자가 ChatGPT 예약 작업으로 따로 돌린다. 프롬프트는
  `references/daangn.md`에 있다. 그 요약은 후보 목록일 뿐이며, 검토 요청이 오면 4~6단계로 처리한다.
- **Aside 사용**: 외부 검색으로 후보 URL을 찾을 때만 쓴다. 저비용 설정(`-s fast --effort low`)으로 한 번 돌리고,
  판정은 직접 한다. 당근 카페처럼 공개 목록을 바로 읽을 수 있는 채널은 Aside 없이 목록에서 고른다.

## 1. 모드 고르기 — 둘러보기 vs 보강

| 모드 | 언제 | 정하는 것 | 결과 |
|---|---|---|---|
| **둘러보기 (기본)** | "문제 둘러보자", "어떤 문제가 있나" | **대상만** (예: 식당·카페 사장) | 장면별로 묶은 원문 최대 3건 |
| **보강** | 수집함의 특정 문제 증거를 채울 때 | 대상 + 장면 + 손실 (씨앗) | 같은 문제의 독립 원문 |

- 둘러보기는 장면을 미리 정하지 않는다. "사장 본인 글 + 손실이 적힌 글"만 찾고, 결과를 장면별로 묶어 보여 준다.
  같은 장면이 여러 번 나오면 그때 보강 모드의 씨앗으로 올린다. 가설을 먼저 세우지 않기 위해서다.
- 보강의 씨앗 = `고객 역할 1개 × 실패 장면 1개 × 손실 1종`. 수집함의 `수집됨` 항목 중 증거수 1~2인 문제에서 고른다.
- 대상을 주지 않으면 채널 전체를 뒤지지 말고 대상 후보 2~3개를 제안해 고르게 한다.

## 2. 보강 모드: 좁게 시작해서 필요할 때만 넓히기

검색어는 사장이 실제로 제목·첫 문장에 쓸 법한 표현으로 만든다 ("1인샵 운영중", "혼자 운영하는데", "저희 가게").
단계마다 결과를 보고 다음 단계로 갈지 정한다. 3건이 차면 즉시 멈춘다.

| 단계 | 범위 | 넓히는 조건 |
|---|---|---|
| L1 | 씨앗 그대로: 역할 표현 + 장면 표현 | 판정 통과 0~1건 |
| L2 | 같은 역할, 장면 동의어 (예: 예약 놓침 → 전화 못 받음, 문의 답장 늦음) | 여전히 0~1건 |
| L3 | 인접 역할, 같은 장면 (미용 → 네일·속눈썹·피부 1인샵) | 여전히 0~1건 |
| 중단 | L3까지 0건이면 채널을 바꾸거나 씨앗을 바꾸자고 보고 | — |

넓힐 때는 "역할" 또는 "장면" 중 하나만 바꾼다. 둘을 동시에 바꾸면 같은 문제의 증거가 아니게 된다.
어느 단계에서 찾았는지를 결과에 함께 적는다 — L3에서 찾은 글은 같은 문제로 묶을지 사용자가 판단해야 한다.

채널별 URL 구조·검색 방식·게시일 확인법은 `references/daangn.md` 처럼 채널 파일을 읽는다.

## 3. Aside 후보 탐색

한 번의 `aside exec`로 단계 하나를 맡긴다. 요청에는 반드시 넣는다.
- 채널과 공개 웹만 볼 것, 로그인·작성 행위 금지
- 기간(최근 12개월, 기준일 명시), 씨앗, 이번 단계의 검색어 3~5개
- 포함·제외 기준, 후보 최대 6개
- 반환 형식: URL, 게시일, 사장임을 보여주는 본문 문장 1개, 손실 문장 1개. 요약·추측 금지, 없으면 0건

Aside 출력의 요약·사례 수는 증거가 아니다. 후보 URL 목록으로만 쓴다.

## 4. 원문 직접 판독

후보마다 원문을 직접 열고(webfetch 또는 curl) 아래를 모두 확인한다. 하나라도 실패하면 제외하거나 경계 사례로 표시한다.

1. **게시일**: 최근 12개월 이내인가 (페이지의 `datePublished` 등으로 확인, 추정 금지)
2. **작성자 = 사장 본인**: "저희 가게", "운영중", "원장입니다"처럼 직접 운영이 본문에 있는가. 매니저·직원·알바·손님 글은 제외
3. **실패 장면**: 반복 업무, 고객 응대, 예약, 정산, 직원 관리 중 무엇이 어떻게 실패했나
4. **명시된 손실**: 시간·돈·매출·손님 손실이 본문 문장으로 있는가. 댓글의 추측은 손실이 아니다
5. **현재 임시방편**: 본문에 있는 것만. 댓글 조언은 임시방편이 아니다
6. **제외 대상 여부**: 단순 불만, 소비자 질문, 플랫폼(당근 등) 자체 기능 불만, 홍보·구인 광고, 뉴스, FAQ, 동일 사건 복제

분류는 `AGENTS.md`의 (a) 독립 고객 실패 사례 / (b) 회복 사례 / (c) 보조 신호 / (d) 중복·제외를 따른다.
조건이 애매하면 "경계 사례"로 따로 보고하고 통과 건수에는 넣지 않는다.

## 5. 결과만 보고

중간 검색 로그, Aside 원시 출력은 보여주지 않는다. 결과는 짧게 이 형식으로 낸다.

```
모드: 둘러보기 | 보강 / 대상(또는 씨앗): <...> / 채널: <채널> / 도달 단계: (보강만) L1~L3
결과: 보관 추천 N건 (+ 경계 M건)

### 1. <한 줄 제목> (보관 추천 | 경계)
- URL:
- 게시일:
- 고객 역할: (근거 문장)
- 실패 상황:
- 현재 임시방편:
- 명시된 손실:
- 비고: 미확인 항목 / 경계 사유

### 제외한 주요 후보
- <제목>: <제외 사유 한 줄>
```

0건이면 억지로 채우지 않고 "0건"과 다음 선택지(대상·씨앗 변경 / 채널 변경)를 보고한다.
항목마다 보관 추천·보류·제외와 이유를 먼저 붙여서, 사용자가 "다시 볼 만한가"만 결정하면 되게 한다.
마지막에 Notion에 저장할 번호를 물어본다. 이 시점까지 아무것도 저장하지 않는다.

ChatGPT 예약 요약을 검토할 때도 같다. 요약의 인용·사례 수를 믿지 말고 원문을 직접 열어 4단계를 다시 한다.

## 6. 승인한 항목만 Notion 저장

사용자가 번호로 승인한 항목만 기존 '문제 수집함' DB에 저장한다. 새 DB나 새 속성은 만들지 않는다.

1. Notion에서 '문제 수집함'을 검색해 data source를 fetch하고 현재 속성·선택지를 확인한다 (스키마가 바뀌었을 수 있다).
2. `원문ID`·`원문링크`로 중복을 조회한다. 이미 있으면 새로 만들지 않고 사용자에게 알린다.
3. 속성 (테이블에는 아래만):
   - `문제`: 한 역할·한 장면·한 손실로 쓴 한 문장
   - `대상`: 고객 역할
   - `상태`: `수집됨`
   - `근거 유형`: 기존 선택지 중에서만. 현재 지출·반복 행동이 원문에 명시되지 않았다면 `정보 부족`
   - `동일 문제 증거수`: 1 (기존 문제와 역할·장면·임시방편이 일치함을 사용자가 확인했을 때만 기존 항목을 +1)
   - `플랫폼`: 기존 선택지 중에서 (`당근 동네생활`, `당근 카페` 등). 새 채널이면 선택지 추가를 사용자에게 먼저 묻는다
   - `원문링크`, `원문ID`(`daangn-community-<글ID>`, `daangn-cafe-<카페ID>-<글ID>` 등), `수집일`(오늘)
   - `점수`는 비운다
4. 본문: 원문 근거(출처·게시일·링크·짧은 발췌·사례 분류), 확인된 사실, 미확인 항목, 경계/제외 사유, 다시 볼 조건.
   해결책·시장성·지불 의사는 쓰지 않는다.
5. 저장 후 생성된 페이지 링크와 속성 값을 표로 보고한다. 검증 실험실 이관이나 validate는 하지 않는다.
