## 1. Skills·MCP 조사와 선택

로컬 `~/.codex/skills`, `~/.agents/skills`, 현재 플러그인 Skill 목록, 저장소 파일을 확인했다. 저장소 전용 SKILL.md나 `.agents/skills`는 발견하지 못했다. 전역에는 시스템 Skill과 Aside, 사업 조사·기획·QA 관련 Skill이 있다. 관련 MCP는 Notion 검색·조회·행 쿼리, Firecrawl 검색·스크랩, 브라우저 제어다. 도구 노출과 실제 접근은 구분했고 Notion 읽기는 성공했다.

Skill은 작업 절차를 안내하며, Node 배치에 자동 탑재되는 분류 엔진이나 스케줄러가 아니다. AI 분류·중복 제거·Notion 저장은 기존 코드를 개선하는 편이 적절하다.

**현재 판정: 당근 자동 수집과 매일 18시 실행으로의 완전 이전은 보류.** 크롤러·스크래퍼·비공개 API·로그인 자동화를 추가하지 않았다. 당근 자료의 자동 AI 분석·저장을 코드에서도 차단했다. 기존 예약은 유지했다. 예약 유지가 해당 예약의 수집 방식이 약관상 허용됨을 뜻하지 않는다.

이전에 필요한 미확인 정보:

2. 기존 원문 URL·원문 게시일·확인 시각·작성자 익명 키·사건 키·채택/제외 이유·Notion 대상 페이지의 대응표. 중복 방지 이력으로 먼저 이전해야 한다.

## 4. 수정 범위와 우선순위

1. `candidate-policy.js`: 출처 제한, 7일·미래 날짜·미확인·접근 불가·회복 사례 구분, 안정적인 원문 식별자, 사람 확인 조건.
2. `collection-pipeline.js`: Telegram/로컬 배치 공통 판정, 단계 집계와 이유, AI 최대 5건, 실패·미분석 보존, 기존 원문 사전 중복, 의미 유사 후보의 증거 추가 검토 계획.
3. 기존 AI 엔진: 원문 400자 절단 제거(12,000자 초과는 수동 검토), 배열 개수·입력 인덱스 대응 검사, 인용 원문 대조, AI가 반환한 사람 확인값·증거수·상태 폐기, 낮은 점수 자동 기각 제거. 기존 공급자 체인은 재사용했다.
4. 기존 Notion 서비스: 스키마 호환 저장·조회, 중복 읽기 실패 시 중단, 페이지네이션, 본문 증거 식별자 재조회, 신규 증거수 0, 사용자 승인 후 본문 증거 후보 추가. 기존 DB 구조 변경 없음.
5. 기존 Telegram: 공통 흐름 사용, 낮은 점수/정보 부족 보존, 동일 프로세스 내 제보 순차 처리, 채팅 허용 ID 필수. 원문 요약·API 응답 오류를 로그에 남기는 일부 경로 축소.
6. 기존 검증 서비스: 자동 승격 차단, 명시적 사용자 승인·사람 검토·동시 1개 조건, 한글 상태 통계 수정, 임의 시작일 제거.
7. `review-collection.js`, `compare-pipeline.js`, 회귀 테스트와 README/AGENTS 갱신. 새 의존성 없음.

같은 문제 판단은 보수적인 글자 유사도 힌트다. 고객 역할·상황·현재 대안이 실제로 일치하는지는 사람이 원문을 판독한다. 자동 병합이나 독립 증거수 증가는 하지 않는다. 본문 추가 메서드도 검토 후보를 기록할 뿐 독립 증거를 승인하지 않는다.

‘광고비 지출+정산 오류+매주 수작업’은 광고/후기 단어로 탈락하던 예시다. 같은 ‘예약 취소’ 제목의 서로 다른 사건도 보존한다. 이 비교는 회수율의 정답 표본 평가가 아니며 새로운 수익 후보 4개가 발견됐다는 뜻이 아니다.

### 기존 데이터 표본: Notion 저장 발췌 1건

[작은 식당의 테이블 장시간 점유](https://app.notion.com/p/3f8eb93112d581afb1e2d49d0e7a63c3)를 확인했다. 당시 페이지는 원문 게시일 9월 26일, 수집일 10월 13일로 기록해 최근 7일 기준보다 오래됐다. 어느 수집 흐름이 저장했는지는 확인되지 않았다. 반복 방문·현재 응대는 기록되어 있지만 실제 매출 손실액·고객 이탈·지불 의사는 미확인이다.

전체 원문 덤프가 아니라 보관된 발췌만 로컬 Git 제외 파일 `data/audit/stored-excerpt.json`로 점검했다. 기존 사전 필터 통과 0/1, 개선 후 `permission_required` 1/1로 이유와 원문을 보존했다. 실제 원문을 외부 AI로 재전송하지 않았다. **실제 데이터의 사업성 개선이나 전체 단계 통과율 비교는 아직 불가능하다.**

테스트는 외부 fetch를 실패하도록 막고 가짜 AI·Notion 클라이언트로 실행했다. `npm test`는 20개 테스트가 모두 통과했다. `node --check`와 `git diff --check`, 기본 review/compare 및 collect/validate의 비활성 안내도 확인했다. 핵심 검증은 출처 전송 차단, 날짜/접근/회복 분류, 원문·사건 중복, 저점수 보존, AI 누락·순서·인용, 공급자 실패 보류, 스키마 불일치, 중복 조회 실패 중단, 사용자 승인과 동시 승격 제한, 증거 본문 추가 재실행이다. 실제 공급자 키·모델 응답과 운영 DB 쓰기는 검증하지 않았다.

## 6. 남은 일과 보안

- 우선 허용된 직접 제보로 실제 소량 표본을 확보한다. 단순 불만/구체적 사건/현재 지출/접근 가능성을 사람이 판독한 정답표와 전 단계 집계를 남긴 뒤 A와 B를 다시 구분한다.
- 실사용 AI 호출과 별도 테스트 DB 쓰기 검증은 아직 수행하지 않았다. 현재 모델 ID는 기존 설정을 유지했으며 유효성·한도는 확인되지 않았다.
- 로컬 배치 CLI는 점검·분석·저장 계획까지만 수행한다. 운영 쓰기, 스케줄 설치, 분산 잠금, 재시도 큐, ChatGPT 이력 가져오기는 후속 범위다. Telegram은 승인된 직접 제보를 기존처럼 수집함에 저장하지만 이번에는 실행하지 않았다.
- 여러 프로세스가 동시에 쓰면 조회 후 생성 사이 경쟁이 가능하다. 현재는 단일 봇 내 순차 처리만 보장한다. 이 한계를 해소하기 전 중복 쓰기 예약을 활성화하지 않는다.
- 기존 Notion 본문은 형식이 제각각이다. 새 증거 식별자 형식 이전의 본문 링크·별칭 전체를 자동으로 사건 목록으로 변환하지 않는다. 이전 대응표와 사람 확인이 필요하다.
- 검색 결과의 동명 항목이 자격 증명 페이지여서 예기치 않게 읽혔다. 추가 조회·값 재인용·파일 복사는 중단했다. **Notion, Telegram, OpenRouter, Groq, Gemini, Naver 자격 증명은 교체 필요 항목**으로 보고한다. 자동 교체·삭제는 하지 않았다.
- 추적 파일과 `.env` Git 경로 이력에서는 `.env`·`.env.local` 추적 이력을 발견하지 못했다. 전체 Git 역사나 외부 저장소의 비밀값 부재를 보증하는 감사는 수행하지 않았다.
- 원문이 포함된 로컬 출력은 `data/` 등 Git 제외 경로에 보관한다. 보고서에는 고객 식별값·키를 담지 않는다. 운영 가이드·DB·Task Board는 이번 변경으로 쓰지 않았다.
