## 출처 후보 — 최종 채택 아님

1. **업무 도구의 공개 지원 글: WordPress.org/WooCommerce 등**
   - 주문·예약·결제·회원 운영 등 고객 업무가 드러나는 게시판으로 좁힌다. 무료 플러그인 사용자나 이미 해결된 장애는 새 유료 수요로 해석하지 않는다.
   - [Plugin FAQ](https://developer.wordpress.org/plugins/wordpress-org/plugin-developer-faq/)의 RSS 경로는 업데이트 관찰 수단이다. 본문 AI 분석·저장 권한을 별도 확인해야 한다.
   - [Forum Guidelines](https://wordpress.org/support/guidelines/)는 광고·유료 도움 제안을 제한한다. 게시글 작성자를 영업 대상으로 수집하지 않는다. 인바운드는 별도의 문제 해결 콘텐츠·자발적 신청 경로를 검토한다.
2. **업무 소프트웨어의 공개 이슈: GitHub Invoice Ninja·ERPNext 등**
   - 개발 오류 전체 대신 청구·정산 등 업무를 하는 사람의 손실·우회·현재 유료 지원을 관찰한다. 개발자가 쓴 요청이나 무료 자가호스팅 선호는 별도 표시한다.
   - [Issues API](https://docs.github.com/en/rest/issues/issues)는 공식 조회 수단이다. [AUP](https://docs.github.com/en/site-policy/acceptable-use-policies/github-acceptable-use-policies#7-information-usage-restrictions)와 API 약관·콘텐츠 권한을 함께 확인한다. 상업적 문제 발굴·외부 LLM 사용이 무조건 허용된다고 판정하지 않았다.
   - 작성자와 비용 결정자의 관계, 실제 연락·검색 콘텐츠 유입 경로, 유지관리자가 해결할 문제인지 확인한다.
3. **예산·인력 투입 요청: 고용24 API 등 허용된 구인·외주 출처**
   - [고용24 공식 API 안내](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do): 기업회원 신청·심사·승인 키가 필요하다. 현재 키·승인 범위를 확인하거나 신청하지 않았다.
   - 인력 예산은 특정 제품 구매 의사나 실제 반복 계약이 아니다. 반복 업무가 드러난 공고를 보조 신호로 읽고 실제 발주·지출을 추가 확인한다. 정규직 업무 전체를 1인 서비스로 대체한다고 가정하지 않는다.
4. **동의받은 직접 제보·운영 경험**
   - 수집·분석 동의가 있는 자체 입력은 자동 접수 경로를 설계하기 쉽다. 고객 확보 수단은 아니므로 어떤 검색 질문·콘텐츠·기존 접점에서 제보자를 만날지 먼저 확인한다. 민감한 고객 정보는 받지 않는다.

Reddit은 [Responsible Builder Policy](https://support.reddithelp.com/hc/en-us/articles/42728983564564-Responsible-Builder-Policy)의 API 승인·상업용 허가 조건 때문에 기본 무료 자동 수집처로 추천하지 않는다. Shopify/Discourse도 공개 포럼·JSON 존재만으로 수집을 허용하지 않는다. Stack Exchange는 API 문서와 별도로 AI 관련 AUP가 있어 이번 주력 자동 수집 후보에서 제외하고 정책 검토가 필요한 보조 출처로만 둔다. 이는 API 경로를 높이 평가한 조사자 의견보다 비판자의 목적별 제한 검토를 우선 수용한 판정이다.

## CEO에게 보낸 첫 질문과 재개 위치

1. 특정 업무 때문에 반복 손실을 겪고 이미 도구·외주에 돈을 쓰는 소규모 사업자·전문직부터 비교할지, 개인 소비자도 동등하게 탐색할지.
2. 영어권 고객에게 글·메일로 판매·지원을 제공할 수 있는지, 한국어권으로 제한할지.
3. 후보가 잡히면 개발 전에 고객 3명의 과거 해결 행동·지출을 확인할 수 있는지, 콘텐츠·신청 반응을 먼저 볼지.

현재 답변 대기. 팀장 제안은 우선 비용 결정자와 반복 업무를 기준으로 조사 범위를 잡는 것이다. 특정 업종·출처 채택·사업 진행·전체 우선순위는 CEO 미결정이다.

다음 사이클은 답변을 반영해 고객 역할 2개만 비교한다. 각각 실패 장면, 반복 손실, 기존 대안, 현재 지출, 인바운드 경로, 1인 운영 부담, 가장 빠른 반증 방법을 작성한다. 공개 원문과 접촉 경로가 함께 확인되지 않으면 자동 수집기를 만들지 않고 다른 역할/장면을 검토한다. 최종 수요 검증은 실제 고객 행동·유료 시험과 반복 이용으로 하며, 공개 사례 수만으로 결제 의사를 확정하지 않는다.
