# 글 발견 구현 시험

**후속 결정:** 사용자 요청으로 Hacker News를 제외하고 시험 CLI·모듈·테스트를 제거했다. 아래 명령과 실행 결과는 과거 기록이며 현재 실행 기능이 아니다. 당시 테스트35개에서 HN전용2개를 제거했다. 로컬 시험 데이터는 삭제하지 않았다.

2026-10-25. 사용자 요청으로 출처·탐색 방법 조사와 최소 구현을 수행했다. 유료 호출·스킬 설치·배포·Notion 쓰기·Telegram 발송 없음. business-research와 research 스킬 사용. 공식 정책 조사 담당 `/root/discovery_feasibility`, 팀장 `/root` 직접 API 검증·통합.

## 출처와 구현 선택

- [HN 공식 API](https://github.com/HackerNews/API)는 공개 데이터 접근과 Ask 목록·item API를 문서화한다. RSS나 검색엔진 없이 ID 목록 → 글 본문을 읽는 경로를 시험했다. 원문 외부 AI 전송·재배포의 포괄적 권한으로 해석하지 않는다.
- 별도 CLI `scripts/discover-hn.js --live --limit 10`은 1회 목록+최대10회 항목 조회. 매 요청15초 제한, 순차 실행. 최대20개 상한. LLM/Notion/Telegram 미사용.
- 글 ID·링크·작성 시각·원문 HTML·초견 여부를 로컬 보존. AI 점수·주제에 의한 숨김 없음. 확인되지 않은 증거 상태 유지. 댓글 본문은 제외.
- `config/sources.json`의 운영 출처 목록은 비어 있다. 시험 명령은 기존 아침 배치와 분리한다.

## 실제 첫 실행

공식 API에서 10건 읽음, 오류0, 초견10, 작성일 최근7일10, AI호출0, Notion쓰기0. 비공개 로컬 출력은 `data/discovery-hn/1792921149177.json`.

표본은 AI·개발 주제에 치우쳤다. 이를 생활·비소프트웨어 유료 거래의 문제10건 발견으로 계산하지 않는다. 기술적 탐색 성공은 확인했지만 주력 출처 채택은 권하지 않는다. 오래된 assistant/가사 서비스 토론이 존재한다는 검색 결과만으로 최신 글 품질을 보장하지 않는다.

두 번째 실사용 실행:10건 읽음·오류0·초견0. 같은10개 ID를 모두 기존으로 판정했다. 출력 `data/discovery-hn/1792921163897.json`. 이는 URL/ID 재발견 방지 시험이며 서로 다른 고객의 동일 사건 판단까지 검증한 것은 아니다. 무API 단위 테스트35개 통과.

## 다른 출처 판정

[접근 조사](discovery-access-2026-10-25.md)에 당근3곳·국내 대안·해외 현장업/소기업 포럼의 접근 결과·공식 이용 조건을 기록했다. 일부 목록/본문 열람은 가능하지만 운영 허용은 미확인이다. 당근 본문은 분석하지 않았다.

- [Airhosts 최근 활동](https://airhostsforum.com/latest)에서 글 링크를 발견하고 본문까지 확인했다. [Major carpet stain](https://airhostsforum.com/t/major-carpet-stain/64973)은 최근 활동 목록에 보여도 원글 작성일이7월이어서 최근7일 새 글이 아니다. [약관](https://airhostsforum.com/tos)의 사용자 글 NC조건 때문에 사업 탐색 자동 운영원으로 활성화하지 않았다.
- [UKBF Recent Posts](https://www.ukbusinessforums.co.uk/aud-feeds/12)는 새 답글·AI답변·홍보가 섞여 있다. 원글 링크2건은 본문 추출 오류라 확인한 글에 세지 않았다. [약관](https://www.ukbusinessforums.co.uk/help/terms-conditions/)의 상업 이용 조건 추가 확인 필요.
- [CFPB 공식 변경 기록](https://cfpb.github.io/api/ccdb/release-notes.html)은2026년9월 소비자 서술 원문 제거를 명시한다. 데이터 API가 있어도 원문 관찰 목적에 맞지 않아 제외했다.

## 판정과 다음 실행

단계별 상태를 `목록 발견`, `본문 접근`, `작성일 확인`, `운영 조건`, `고객 경험 품질`로 분리한다. 공개 페이지 접근 성공은 자동 운영 허용이나 실시간 무결성을 증명하지 않는다. 먼저 출처 품질과 운영 경로를 확보하고 이후 기존 보고 기능에 연결한다. 현재 전체 자동 탐색 시스템 완료 아님.

추가 설치가 필요한 스킬 없음. 브라우저 동적 렌더링이 필요한 출처가 확정될 때만 브라우저 자동화 의존성을 검토한다. 문의문은 작성만 했고 발송하지 않았다.
